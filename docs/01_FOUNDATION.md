# 1단계 기획 및 구현 문서: Foundation

## 목표

게임을 시작하고, 조작하고, 실패하고, 다시 시작할 수 있는 공통 기반을 안정화한다.

## 플레이어 경험

플레이어는 사무실 입구에서 대기하다가 이동 입력을 누르면 퇴근길을 시작한다. 카메라는 캐릭터 뒤를 따라가고, 장애물에 충돌하면 짧은 낙하/피격 상태 뒤 게임오버 화면이 나온다.

## 구현 범위

- `GameScene` 기본 구성 정리
- 플레이어 프리팹 구조 확정
- 카메라 추적값 조정
- 게임 상태 전환 검증
- 입력 체계 검증
- 기본 UI 상태 표시
- 테스트용 장애물 1종과 목표 트리거 1종 배치

## 와이어프레임 에셋

| 에셋 | 형태 | 용도 |
| --- | --- | --- |
| `WF_PlayerCapsule` | 캡슐 | 플레이어 기준 충돌체 |
| `WF_GroundTile` | 얇은 큐브 | 진행 바닥 |
| `WF_LaneMarker` | 가는 큐브 3줄 | 레인 위치 가시화 |
| `WF_StartZone` | 투명 박스 | 시작 위치 확인 |
| `WF_DeathPlane` | 넓은 박스 | 낙하 실패 테스트 |

## 구현 작업

1. 씬 루트 정리
   - `Managers`, `Player`, `CameraRig`, `LevelRoot`, `UIRoot`로 계층을 나눈다.
   - `GameManager`, `DifficultyManager`, `GroundSpawner`, `ObstacleSpawner`의 참조 누락을 확인한다.

2. 플레이어 기준값 확정
   - 레인 폭은 기존 `2.5`를 기준으로 둔다.
   - 점프 높이는 지면 장애물보다 명확히 높게 유지한다.
   - 슬라이드 높이는 공중 장애물 아래를 통과할 수 있게 조정한다.

3. 카메라 확정
   - 후방 3인칭 카메라는 플레이어의 Z 이동을 따라간다.
   - 장애물 예측이 가능하도록 전방 시야를 충분히 확보한다.
   - 충돌/게임오버 시 카메라가 과도하게 흔들리지 않게 한다.

4. 상태 전환 검증
   - Ready에서 이동 입력으로 Playing 진입
   - 충돌 시 Dying 또는 GameOver 진입
   - Restart 시 `Time.timeScale` 복구
   - MainMenu와 GameScene 전환 확인

5. 클리어 상태 준비
   - `GameManager.GameState`에 `GameClear`를 추가할 수 있도록 상태 전환 흐름을 검토한다.
   - 실제 클리어 화면 구현은 6단계에서 진행하되, 게임오버와 충돌하지 않는 상태 구조를 먼저 잡는다.

6. 테스트 장애물/목표 배치
   - 지면 장애물 1개를 고정 배치해 충돌과 게임오버를 검증한다.
   - 초록 목표 트리거 1개를 고정 배치해 향후 `StageExitTrigger` 흐름을 검증한다.

7. UI 최소 구성
   - Ready 안내
   - 진행 거리
   - 현재 단계
   - GameOver 패널
   - Restart 버튼

## 완료 기준

- 에디터에서 `GameScene`을 실행하면 Ready 상태로 시작한다.
- 키보드와 터치 입력이 모두 기본 동작한다.
- 플레이어가 3개 레인 사이를 이동하고, 점프/슬라이드가 충돌체와 일치한다.
- 게임오버 후 재시작이 정상 동작한다.
- 테스트 목표 트리거 접촉을 감지할 수 있다.
- 콘솔에 치명적인 NullReference 또는 MissingReference 오류가 없다.

## 테스트 체크리스트

- W/위 입력으로 시작되는가
- A/D 또는 좌우 방향키로 레인 이동이 되는가
- Space 점프가 지면에서만 실행되는가
- Shift 슬라이드 후 콜라이더가 원상복구되는가
- 충돌 시 중복 게임오버가 발생하지 않는가
- 목표 트리거가 한 번만 감지되는가
- 재시작 후 `Time.timeScale`이 1로 돌아오는가
