# 5단계 기획 및 구현 문서: Stage 3 Commute

## 목표

가장 어려운 구간인 도심 밤거리와 만원 지하철을 만든다. 동적인 장애물, 군중 압박, 비 오는 분위기를 와이어프레임으로 먼저 구현한다.

## 플레이어 경험

건물 밖은 비가 오고 길은 붐빈다. 플레이어는 우산, 물웅덩이, 스마트폰을 보는 시민을 피해 지하철 승강장으로 들어간다. 열차 안에서는 승객 사이를 비집고 지나 집 근처 역에서 내려야 한다.

## 레벨 구조

- 목표 거리: 360m
- 참고 시간: 약 90초
- 구간 A: 비 오는 밤거리
- 구간 B: 지하철 승강장
- 구간 C: 지하철 객실 내부
- 목표: 집 근처 역 출구 트리거

초기에는 하나의 연속 러너 구간으로 만들고, 배경 프리셋만 거리 -> 승강장 -> 객실 순서로 바꾼다.

## 와이어프레임 에셋

| 이름 | 형태 | 기능 |
| --- | --- | --- |
| `WF_RainStreetTile` | 바닥 큐브 | 야외 지면 |
| `WF_Umbrella_Air` | 얇은 반원 대체 큐브 | 시야/슬라이드 장애물 |
| `WF_Puddle_Slow` | 얇은 파랑 박스 | 감속 |
| `WF_PhoneZombie_LaneBlock` | 캡슐 | 느린 보행자 |
| `WF_SubwayScreenDoor` | 얇은 벽 | 레인 차단 |
| `WF_TrainDoorGoal` | 초록 박스 | 객실 진입 |
| `WF_PassengerCrowd` | 캡슐 묶음 | 레인 차단 |
| `WF_Handle_Air` | 작은 가로 큐브 반복 | 슬라이드 장애물 |
| `WF_StationExitGoal` | 초록 박스 | Stage 4 전환 |

## 장애물 패턴

### 밤거리

- 펼쳐진 우산: Air 타입, 슬라이드 회피
- 스마트폰 보행자: LaneBlock 타입, 느린 좌우 이동 가능
- 물웅덩이: SlowZone 타입

### 승강장

- 스크린도어 기둥: LaneBlock 타입
- 하차 승객: ApproachMovement 또는 좌우 이동
- 가방: Ground 타입

### 객실 내부

- 승객 군중: 2레인 차단 패턴
- 손잡이/광고판: Air 타입
- 닫히는 문: 타이밍형 LaneBlock

## 구현 작업

1. 서브 구간 프리셋
   - `StageSegmentDefinition` 또는 간단한 거리 기준 분기를 만든다.
   - 0-120m: Street
   - 120-220m: Platform
   - 220-360m: TrainInterior

2. 동적 장애물
   - `ApproachMovement`를 활용해 플레이어 방향으로 다가오는 시민을 만든다.
   - 좌우 이동 장애물이 필요하면 `SideToSideMovement`를 추가한다.

3. 군중 패턴
   - 캡슐 여러 개를 묶은 프리팹을 만든다.
   - 반드시 하나 이상의 탈출 레인을 남긴다.

4. 비와 분위기
   - MVP에서는 파티클보다 얇은 파란 선/투명 평면을 사용한다.
   - 조명은 어둡게 하되 장애물 색은 명확히 보이게 한다.

5. 객실 내부 압박
   - 배경 벽을 좁게 배치해 답답함을 만든다.
   - 실제 충돌 폭은 너무 좁히지 않는다.

6. 역 출구 전환
   - `StageManager`가 360m 도달 시 `WF_StationExitGoal`을 활성화한다.
   - `WF_StationExitGoal` 접촉 시 Stage 4로 전환한다.
   - 난이도 속도를 낮추고 따뜻한 조명으로 바꾼다.

## 완료 기준

- Stage 3 안에서 거리, 승강장, 객실 분위기가 구분된다.
- 이전 스테이지보다 어렵지만 피할 수 없는 패턴은 없다.
- 동적 장애물이 플레이어 반응 시간을 침해하지 않는다.
- Stage 4로 정상 전환된다.

## 테스트 체크리스트

- 어두운 조명에서도 장애물 타입이 구분되는가
- 군중 프리팹이 콜라이더를 과도하게 넓히지 않는가
- 이동 장애물이 풀링 후 상태를 초기화하는가
- 객실 벽이 카메라와 충돌하거나 시야를 막지 않는가
