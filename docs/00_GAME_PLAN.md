# 퇴근길 서바이벌 전체 기획서

## 한 줄 설명

피곤한 직장인이 사무실, 로비, 도심, 지하철을 지나 집의 침대까지 도착하는 3인칭 3D 회피 러너 게임.

## 핵심 목표

- 플레이어는 전진, 후진 감속, 좌우 레인 이동, 점프, 슬라이드로 장애물을 회피한다.
- 스테이지는 하나의 귀가 여정으로 이어지며, 각 구간은 다른 장애물 규칙과 분위기를 가진다.
- 초기 제작은 와이어프레임/그레이박스로 진행하고, 실제 에셋은 검증된 구조 위에 나중에 입힌다.
- 첫 완성 목표는 짧지만 끝까지 플레이 가능한 수직 슬라이스다.

## 현재 프로젝트 기준

이미 구현된 기반:

- Unity 6 URP 3D 프로젝트
- `PlayerController`: 3레인 이동, 전후 가속, 점프, 슬라이드, 터치 입력
- `CameraFollow`: 3인칭 추적 카메라
- `GameManager`: Ready, Playing, Dying, GameOver 상태
- `DifficultyManager`와 `DifficultyData`: 시간 기반 속도와 스폰 간격
- `GroundSpawner`: Z축 기반 지면 타일 재활용
- `ObstacleBase`, `IObstacleEffect`, `IObstacleMovement`: 장애물 효과/이동 조합 구조
- 기본 프리팹: 지면 타일, 지면/공중/레인 장애물

따라서 새 기획은 완전한 백지 개발보다 기존 러너 기반을 확장하는 방향이 맞다.

## 보완이 필요한 초기 기획

### 1. 장르 범위 고정

초기 문서는 스테이지별 장면성이 좋지만, 구현 관점에서는 러너, 잠입, 웨이브 방어, 리듬 게임이 섞여 있다. 초반에는 모든 미니게임을 동시에 만들지 말고 3레인 러너를 중심으로 통일한다.

권장:

- Stage 1-3은 동일한 조작과 장애물 시스템을 공유한다.
- 엘리베이터 버티기와 사원증 리듬 입력은 MVP 이후 확장 기능으로 둔다.
- Stage 4는 짧은 보상 구간과 결과 화면으로 마무리한다.

### 2. 스테이지 전환 규칙

각 스테이지가 언제 끝나는지 명확해야 한다. MVP에서는 `거리 기준`을 공식 종료 조건으로 사용한다. 시간은 밸런싱 참고값으로만 본다.

권장 기준:

- Stage 1: 사무실 복도 220m 진행 후 엘리베이터 도착
- Stage 2: 로비 160m 진행 후 건물 밖 도착
- Stage 3: 도심/지하철 360m 진행 후 집 근처 도착
- Stage 4: 저속 보상 구간 80m 진행 후 침대 트리거 진입

참고 플레이 시간:

- Stage 1: 약 60초
- Stage 2: 약 45초
- Stage 3: 약 90초
- Stage 4: 약 20-30초

### 3. 피로도/집 도착 동기

단순 생존보다 주제에 맞는 수치가 있으면 게임 정체성이 강해진다.

권장:

- `체력` 대신 `멘탈/피로도`를 사용한다.
- 충돌하면 피로도가 증가하고, 최대치에 도달하면 게임오버.
- 집에 가까워질수록 UI 색과 음악이 안정적으로 바뀐다.

### 4. 장애물 타입 표준화

스테이지별 이름은 달라도 기능은 재사용 가능한 타입으로 묶는다.

| 타입 | 회피 방식 | 사무실 | 로비 | 도심/지하철 |
| --- | --- | --- | --- | --- |
| Ground | 점프 | 서류 더미 | 청소 카트 | 낮은 가방 |
| Air | 슬라이드 | 열린 캐비닛 문 | 보안 바 | 손잡이/광고판 |
| LaneBlock | 레인 변경 | 파티션 끝 | 게이트 | 승객 군중 |
| SlowZone | 속도 저하 | 믹스커피 | 물걸레 바닥 | 물웅덩이 |
| Chaser | 압박 | 상사 | 보안 요원 | 막차 알림 |

초기 구현은 기존 3종 장애물에 SlowZone과 Chaser를 단계적으로 추가한다.

### 5. 와이어프레임 에셋 규칙

이미지를 나중에 붙이려면 임시 에셋도 규칙적이어야 한다.

- 모든 임시 에셋은 `WF_` 접두사를 붙인다.
- 충돌 크기는 실제 에셋 교체 후에도 유지할 기준 박스로 만든다.
- 색은 기능별로 고정한다: 점프 장애물 빨강, 슬라이드 장애물 파랑, 레인 차단 노랑, 안전 목표 초록.
- 각 스테이지의 배경물은 플레이 충돌과 장식 충돌을 명확히 분리한다.

## 전체 게임 흐름

```text
MainMenu
  -> Stage 1: Office
  -> Stage 2: Lobby
  -> Stage 3: Commute
  -> Stage 4: Home
  -> Result
```

초기에는 하나의 `GameScene` 안에서 구간 테마와 스폰 테이블만 바꾸고, 이후 필요하면 씬을 분리한다.

## 스테이지 진행 시스템

MVP의 스테이지 진행은 다음 공통 컴포넌트로 관리한다.

| 구성 | 책임 |
| --- | --- |
| `StageManager` | 현재 스테이지, 진행 거리, 전환 이벤트 관리 |
| `StageDefinition` | 목표 거리, 배경 프리셋, 장애물 테이블, 속도 배율 보관 |
| `StageExitTrigger` | 목표 지점 접촉 시 다음 스테이지 또는 클리어 요청 |
| `PlayerVitals` | 피로도, 충돌 횟수, 생존/실패 판정 관리 |

스테이지 전환은 거리 조건을 만족하면 목표 트리거를 활성화하고, 플레이어가 해당 트리거에 닿으면 다음 `StageDefinition`을 적용하는 방식으로 시작한다.

## 공통 플레이 규칙

- 조작: W/위 전진, S/아래 감속, A/D 또는 좌우 레인 변경, Space 점프, Shift 슬라이드
- 모바일: 좌우 스와이프 레인 변경, 위 스와이프/탭 점프, 아래 스와이프 슬라이드
- 실패: 피로도 최대 또는 치명 장애물 충돌
- 성공: Stage 4의 침대 트리거 도달
- 점수: 이동 거리, 남은 피로도, 충돌 횟수, 귀가 시간으로 계산

## 개발 마일스톤

| 단계 | 목표 | 완료 조건 |
| --- | --- | --- |
| 1. Foundation | 공통 게임 기반 안정화 | 시작, 이동, 카메라, 게임오버가 안정적으로 동작 |
| 2. Core Loop | 반복 플레이 가능한 러너 완성 | 장애물 회피, 난이도 증가, UI 점수 표시 |
| 3. Office | 첫 스테이지 완성 | 사무실 테마 장애물과 전환 트리거 동작 |
| 4. Lobby | 두 번째 스테이지 완성 | 엘리베이터/로비 와이어프레임과 타이밍 장애물 동작 |
| 5. Commute | 핵심 고난도 구간 완성 | 군중/열차/도심 장애물 패턴 동작 |
| 6. Home & Polish | 엔딩과 품질 정리 | 집 도착, 결과 화면, 사운드/연출 1차 적용 |

## 리스크와 대응

- 스테이지별 욕심이 커질 수 있다: MVP에서는 모든 스테이지를 같은 러너 규칙으로 묶는다.
- 에셋 제작이 병목이 될 수 있다: 기능 검증 전까지 큐브/실린더만 사용한다.
- 난이도 곡선이 급격할 수 있다: 거리 기반 스폰 테이블과 피로도 UI를 먼저 만든다.
- 충돌 판정이 불공정해질 수 있다: 모든 장애물 프리팹에 기준 콜라이더와 회피 방식 라벨을 둔다.
- 기존 코드가 무한 러너 중심이다: 스테이지 전환은 씬 분리보다 테마 데이터 교체로 먼저 구현한다.
